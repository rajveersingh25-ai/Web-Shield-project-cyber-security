Section 01

Abstract

WebShield is a passive, read-only web security auditing tool developed as a capstone project for the IBM SkillsBuild Cybersecurity Bootcamp. It provides a browser-based interface for assessing the security configuration of any publicly accessible website without requiring specialist knowledge or command-line tools.

The application analyses HTTP response metadata — security headers, CORS policies, cookie attributes, HTTPS enforcement, and server information disclosure — and aggregates the findings into a risk score (0–100), a letter grade (A–F), and a colour-coded recommendations table. Results can be downloaded as CSV for inclusion in security reports.

The tool is built on Python 3, Streamlit, Requests, and Pandas as a single self-contained file. It incorporates SSRF protection, input sanitisation, and strict passive-only constraints, mapping directly to OWASP Top 10 – A05: Security Misconfiguration.

Section 02

Problem Statement

Security misconfiguration is consistently ranked among the most prevalent web application vulnerabilities. According to the OWASP Top 10 (2021), A05: Security Misconfiguration encompasses missing security headers, overly permissive CORS policies, insecure cookie attributes, and server information disclosure — and affects a significant proportion of tested applications.

Despite free scanning services existing online, developers often lack a quick, self-hosted, auditable tool they can use during local development. Existing online scanners require sending URLs to third-party services, raising privacy concerns.

The Gap: Developers need a fast, transparent, local tool to check security headers and CORS configuration at any point in the development lifecycle — without sending URLs to external parties.

WebShield addresses this gap by providing a lightweight, self-hosted tool with a modern user interface that any developer can run on their own machine with a single command: streamlit run app.py.

Data Flow Summary

  1. User submits a URL via the Streamlit text input and clicks Run Scan.
  2. validate_url() checks format, resolves DNS, and blocks private IPs.
  3. fetch_url() sends a GET request to the target and returns the response.
  4. Each check function receives the response and returns a list of finding dicts.
  5. run_scan() merges all findings and calls calculate_risk_score().
  6. The result is stored in st.session_state and rendered on the page.
Section 06

Module Descriptions

validate_url()

Accepts only URLs beginning with http:// or https://. Resolves the hostname via socket.getaddrinfo() and checks all returned IPs against a blocklist of private CIDR ranges (RFC 1918, loopback, link-local) to prevent SSRF.

fetch_url()

Centralised HTTP request helper wrapping requests.request() with a 10-second timeout and a realistic browser User-Agent. Catches all connection, SSL, and timeout exceptions and returns None on failure.

check_security_headers()

Iterates over six known security headers. For each one it checks presence in the response (case-insensitive) and returns a finding with the current value, severity, explanation, and recommended fix string.

check_cors()

Sends three GET requests with crafted Origin headers (https://evil-example.com, null, https://attacker.com). Inspects Access-Control-Allow-Origin (ACAO) and Access-Control-Allow-Credentials (ACAC). Flags wildcard ACAO, reflected origin, and wildcard + credentials.

check_cookies()

Reads all Set-Cookie headers via the underlying urllib3 response to preserve duplicates. For each cookie checks for the Secure, HttpOnly, and SameSite tokens (case-insensitive).

check_https()

Checks: (a) whether the URL scheme is https; (b) whether the HTTP version redirects to HTTPS; (c) whether Server, X-Powered-By, X-AspNet-Version, or X-Generator headers disclose software identity.

calculate_risk_score()

Assigns penalty points per finding (High=15, Medium=7, Low=3), sums and clamps to 100, and maps to a letter grade: A≤10, B≤25, C≤45, D≤65, F>65.

Section 09

Challenges and Solutions

ChallengeSolution
SSRF Prevention
User could scan internal services		 Resolve hostname via DNS before requesting; check all returned IPs against blocked CIDR ranges using the ipaddress stdlib module.
Duplicate Set-Cookie headers
requests merges duplicate headers		 Access response.raw.headers.getlist("Set-Cookie") from the underlying urllib3 response to retrieve all cookies individually.
CORS false positives
Many sites don't set ACAO at all		 Only flag a CORS issue when ACAO is explicitly present and problematic. Absent ACAO is treated as "no issue found".
Streamlit state management
Results lost on re-render		 Store the full result dict in st.session_state so it persists across interactions without page reload.
Timeout on slow hosts
Scans could hang indefinitely		 Set a 10-second timeout on all requests. Wrap in a broad exception handler — return None and surface a user-friendly error message.
Dark-theme styling in Streamlit
Default theme inconsistent		 Inject custom CSS via st.markdown(..., unsafe_allow_html=True) for badges, grade circles, section headers, and the disclaimer box.
Section 10

Conclusion

WebShield successfully meets all project objectives. It provides a clean, modern, browser-based interface for passive web security auditing that is accessible to developers without a security background, while remaining technically rigorous for those who are familiar with HTTP security concepts.

The project demonstrates practical application of several core cybersecurity principles covered in the IBM SkillsBuild Cybersecurity Bootcamp: security misconfiguration detection, OWASP Top 10 mapping, input validation, SSRF prevention, and responsible disclosure (passive-only, ethical-use warnings).

The entire application is contained in a single, well-structured app.py file (~380 lines), making it easy to read, review, and extend.

✅ Key Outcome: A fully functional, submission-ready cybersecurity tool that demonstrates both secure development practices and web security auditing knowledge, launched with one command: streamlit run app.py.
